# BinPngConverter — 画像 ⇔ .bin 変換 ＋ WAV 変換ツール

このゲーム機用の画像データ（`.bin`）と PNG を相互に変換し、WAV を本体で鳴らせる形式に変換する Windows 用ツールです。
`BinPngConverter.exe` をダブルクリックで起動します（.NET Framework 4.5 以上。Windows 10/11 には最初から入っています）。
exe のアイコンにファイルをドロップして起動すると、そのファイルが最初からリストに入ります。

## .bin 形式

- RGB565・リトルエンディアン・ヘッダなし（1 ピクセル 2 バイト、左上から横方向に並ぶ）
- マゼンタ `0xF81F` は透過色

ヘッダが無いので、.bin → PNG のときは幅と高さの指定が必要です。

## 画面

| 位置 | 内容 |
|------|------|
| 左上 | 画像 → .bin。PNG / JPG / BMP / GIF / TIFF をドロップ |
| 右上 | .bin → PNG。.bin をドロップし、幅・高さを入力 |
| 中段 | WAV → 本体用 WAV。WAV をドロップ |
| 中段 | 出力先フォルダ（参照ボタン、またはフォルダをドロップ） |
| 右下 | 実行 |

- ウィンドウのどこにドロップしても、拡張子で左右に振り分けます。フォルダをドロップすると中のファイルをまとめて追加します。
- 出力ファイル名は元の名前の拡張子を変えたものです（`player.png` → `player.bin`）。同名のファイルは上書きされます（ログに `[上書き]` と表示）。
- WAV の出力名も元と同じ名前（`.wav`）です。元ファイルと同じ場所に出力する場合だけ、元を上書きしないよう `名前_conv.wav` になります。
- 「元ファイルと同じフォルダ」にチェックすると、出力先は各ファイルと同じフォルダになります。
- 最後に使った出力先は `BinPngConverter.last_dir.txt`（exe と同じ場所）に保存されます。

### 画像 → .bin のオプション

- **透明部分をマゼンタ (0xF81F) にする**（初期値 ON）
  - 不透明度 50% 未満のピクセルを透過色にします。
  - 元画像にある本物のマゼンタは、透明扱いにならないよう `0xF83F`（見た目はほぼ同じ）に置き換えます。その場合はログに件数が出ます。
  - OFF にすると、半透明部分は黒の上に合成します。
- **サイズ変更**: 指定した幅×高さに縮小・拡大してから変換します。

### .bin → PNG のオプション

- 幅・高さの自動推定は次の順に試します。
  1. ファイル名に `64x32` のような表記があればそのサイズ
  2. よく使うサイズ（320x240、100x100 など）
  3. 正方形
- 推定できないときや違うときは、表の「幅」「高さ」を直接入力してください。幅だけ入れると高さは自動で計算されます。サイズが合わない行は赤くなります。
- **マゼンタ (0xF81F) を透明にする**（初期値 ON）: 透過色を PNG の透明として出力します。

### WAV → 本体用 WAV

本体（`machine.play_wav` / `machine.play_se`）が読めるのは **16bit PCM・モノラルかステレオ** の WAV だけです。
それ以外の WAV を、本体で鳴らせる形式に変換します（一方向のみ）。

- **読める WAV**
  - 8/16/24/32bit の整数 PCM、32/64bit の浮動小数点、A-law・μ-law
  - WAVE_FORMAT_EXTENSIBLE 形式、3ch 以上のファイル
  - MP3 や ADPCM などの圧縮形式は読めません。先に他のソフトで PCM の WAV にしてください。
- **出力**
  - 16bit PCM の WAV で、fmt と data だけの最小構成です（メタデータは削除）。
- **用途**
  - BGM：44100Hz にします。本体の出力周波数と同じなので、補間なしでそのまま鳴ります。
  - SE：11025Hz にし、32KB を超えるファイルを赤く表示します。`play_se` は data が 32KB（32768 バイト）までです。目安は 11025Hz モノラルで約 1.49 秒、22050Hz で約 0.74 秒までです。
  - どちらの用途でも、周波数はあとから変更できます。
- **周波数**
  - 44100 / 32000 / 22050 / 16000 / 11025 / 8000Hz と「元のまま」から選べます。
  - 変換は高品質なフィルタ（Kaiser 窓 sinc）で行い、折り返しノイズは約 -90dB に抑えます。
- **チャンネル**
  - 初期値は「モノラル」で、全チャンネルを平均します。スピーカー 1 個なら、モノラルにすると SD の読み込み量が半分になります。
  - 「元のまま」にすると、ステレオはステレオのまま出力します。3ch 以上の場合は先頭 2ch を使います。
- **音量をそろえる**
  - 一番大きい音（ピーク）を指定の dB にそろえます。初期値は -3dB です。
  - OFF の場合は音量を変えません。ただし 16bit に収まらない場合だけ、音割れしないよう下げます（ログに表示）。
- **低音カット**
  - 指定した周波数より低い音を弱めます（2 次ハイパスフィルタ）。小さいスピーカーでは低音が鳴らずに歪みの原因になるので、音割れするときは 150〜300Hz くらいを試してください。
  - 本体では BGM と SE を足し合わせて鳴らします。重なって音割れするときは、ピークを -6dB 前後にするのも効果があります。
- **その他**
  - 16bit に減らすときは、TPDF ディザをかけます。
  - 元が 16bit 以下の PCM で、周波数・チャンネル・音量・低音カットのどれも変えない場合は、音のデータを 1 ビットも変えずにヘッダだけ整理します。

## コマンドライン

```
BinPngConverter.exe --png2bin 入力画像 出力.bin [--nokey] [--size WxH]
BinPngConverter.exe --bin2png 入力.bin 幅 高さ 出力.png [--nokey]
BinPngConverter.exe --wav 入力.wav 出力.wav [--rate 44100|keep] [--keepch] [--peak -3] [--hpf 200]
```

`--wav` の既定は 44100Hz・モノラル・音量そのまま・低音カットなしです。

## ビルド

`BinPngConverter.cs` 1 ファイルだけで構成されています。

- Windows 付属のコンパイラでビルドする場合:
  ```
  C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe /target:winexe /r:System.Windows.Forms.dll /r:System.Drawing.dll /out:BinPngConverter.exe BinPngConverter.cs
  ```
- Mono でビルドする場合:
  ```
  mcs -codepage:65001 -target:winexe -sdk:4.5 -r:System.Windows.Forms.dll -r:System.Drawing.dll -out:BinPngConverter.exe BinPngConverter.cs
  ```

## 確認済みの内容

- 画像 → .bin の結果は、独立に書いた Python の変換処理とバイト単位で一致しました。対象は透明部分と本物のマゼンタを含むランダム画像です。
- JadeLantern の `img/*.bin` 12 個で .bin → PNG → .bin を往復し、すべて元のファイルと完全に一致しました。
- WAV は、テスト信号で作った次のファイルを変換し、結果を確認しました。
  - 8/16/24/32bit 整数、32/64bit 浮動小数点、EXTENSIBLE 形式、A-law・μ-law、6ch、奇数サイズのチャンクを含むファイル
  - サイン波の振幅が保たれること（誤差 1% 以内）
  - 48k → 22.05k で 15kHz の折り返しが -90dB であること
  - 低音カット 200Hz で 50Hz が -24dB、1kHz が -0.01dB になること
  - ピークをそろえたときの誤差が 0.05dB 以内であること
  - 無変換のときにデータが完全一致すること
  - 壊れたファイルと MP3 でエラーになること
- 3 分の 48kHz 24bit ステレオの変換時間は約 4 秒でした。
